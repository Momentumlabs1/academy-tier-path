# Particle art — the academy's header banners

Every page header in the member app opens on a generated particle field. They are
**not** stock images: `render.html` is the source, the JPGs in `src/assets/` are
the build output. Regenerate them, add a variant for a new section, retune the
palette — it is all in one file.

## Why it looks the way it does

The whole family shares one treatment: small dots, additive blending on black, a
lit ridge that fades down into the body, a few blown-out sparkles. What changes
per page is only the **silhouette**, and the silhouette is the message:

| variant | shape | page | says |
|---|---|---|---|
| `pulse` | rings leaving a source | signals | a channel broadcasting |
| `ascent` | a staircase climbing right | lessons | one step at a time |
| `lattice` | a measured field of ticks | tools | instruments, precision |
| `gate` | two masses parted by light | unlocks | the moment it opens |
| `calm` | one low, even swell | settings | nothing here demands you |
| `burst` | a plume from a single point | notifications | something just arrived |
| `horizon` | a wide sweep opening right | dashboard | the whole view |

`src/assets/art-dune.jpg` (the Tier page) is **not** generated by this tool. It
predates it and is the picture the family was modelled on — leave it alone.

## Two things that will bite you

**Compose in screen space, not in 3D.** The first version built each shape on a
3D surface and projected it. Every variant came out identical: the perspective
compressed them all into the same diagonal band and the slab thickness smeared
away what structure survived. Rings, stairs and grids were all invisible. The
banner is ~400px wide in the header — internal texture does not survive that,
silhouette does.

**Use a real PRNG.** An LCG with a short period silently caps how dense the field
can get: past its period it redraws the same points, so raising the particle
count changes nothing at all and you will spend an hour wondering why the image
stays thin. `render.html` uses mulberry32.

## Regenerating

```bash
node tools/particle-art/render.mjs                 # the whole shipped set
node tools/particle-art/render.mjs pulse 212 5     # one-off: variant hue seed
```

Needs `playwright-core` and a Chromium binary (`PW_CHROMIUM=/path/to/chrome` if
Playwright cannot find one). Install `sharp` to get JPGs directly; without it the
PNGs are left in a temp dir for you to convert.

You can also just open `render.html` in a browser and drive it with query
parameters: `?v=pulse&hue=212&seed=5&w=1800&h=750&n=900000`.

## Adding a banner for a new section

1. Add a branch to `profile(x)` in `render.html` returning `edge` / `mass` /
   `deep`. Keep the mass in the **right half** — the header only shows the right
   ~58% of the image.
2. Add a row to `BANNERS` in `render.mjs`.
3. Render, then use it via `PageHero`'s `art` prop.

Keep the hue between roughly 205 and 230. Below that it drifts to cyan, above it
to violet; both fight the logo.
